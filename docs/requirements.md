# 要件定義書

## 1. プロジェクト背景

### 1.1 課題
- iCloudに写真が保存されている状態で、誤ってGoogle Photos同期をONにしてしまった
- 結果としてGoogleストレージが逼迫している
- 不要な写真を一括で削除する必要がある

### 1.2 制約
- Google Photos APIは写真の削除機能を提供していない
- Playwrightによるブラウザ自動化で対応する

## 2. 機能要件

### 2.1 認証機能
| ID | 要件 | 優先度 | 状態 |
|----|------|--------|------|
| AUTH-01 | 個人のGoogleアカウントでログインできる | 必須 | 実装済み |
| AUTH-02 | ログイン状態を維持できる（セッション保持） | 必須 | 実装済み |
| AUTH-03 | アプリ画面から「ログイン」ボタンで認証を開始できる | 必須 | 実装済み |
| AUTH-04 | アプリ画面から「ログアウト」ボタンでセッションをクリアできる | 推奨 | 実装済み |

### 2.2 日付範囲指定機能
| ID | 要件 | 優先度 |
|----|------|--------|
| DATE-01 | Web UI上で開始日を指定できる | 必須 |
| DATE-02 | Web UI上で終了日を指定できる | 必須 |
| DATE-03 | カレンダーUIで日付を選択できる | 推奨 |

### 2.3 ドライラン機能
| ID | 要件 | 優先度 |
|----|------|--------|
| DRY-01 | 削除対象の写真一覧を表示できる | 必須 |
| DRY-02 | 削除対象の総枚数を表示できる | 必須 |
| DRY-03 | 実際の削除は行わない | 必須 |

### 2.4 削除機能
| ID | 要件 | 優先度 |
|----|------|--------|
| DEL-01 | 指定日付範囲の写真を一括でゴミ箱に移動できる | 必須 |
| DEL-02 | 削除前に確認プロンプトを表示する | 必須 |
| DEL-03 | ゴミ箱を空にする操作（完全削除）はスコープ外。Google Photos側で一括実行できるためツールでは行わない | スコープ外 |

### 2.5 進捗表示機能
| ID | 要件 | 優先度 |
|----|------|--------|
| PROG-01 | 処理済み枚数を表示できる | 必須 |
| PROG-02 | 総枚数に対する進捗を表示できる | 必須 |
| PROG-03 | リアルタイムで更新される | 必須 |

### 2.6 レジューム機能
| ID | 要件 | 優先度 |
|----|------|--------|
| RES-01 | エラー発生時に処理状態を保存できる | 必須 |
| RES-02 | 保存した状態から処理を再開できる | 必須 |
| RES-03 | 処理済みの写真はスキップする | 必須 |

### 2.7 エラーハンドリング
| ID | 要件 | 優先度 |
|----|------|--------|
| ERR-01 | 個別の写真削除失敗時にリトライする | 必須 |
| ERR-02 | リトライ回数は3回とする | 必須 |
| ERR-03 | リトライ間隔は指数バックオフとする | 必須 |

### 3.2 可用性
| ID | 要件 |
|----|------|
| AVAIL-01 | ローカルのmacOS上で動作する |

## 4. ユースケース

### UC-01: 日付範囲を指定して写真を削除する

**アクター**: ユーザー

**事前条件**:
- アプリケーションが起動している
- Googleアカウントにログイン済み

**基本フロー**:
1. ユーザーがWeb UIで開始日と終了日を入力する
2. ユーザーが「ドライラン」ボタンをクリックする
3. システムが削除対象の写真一覧と総枚数を表示する
4. ユーザーが内容を確認し「削除実行」ボタンをクリックする
5. システムが確認ダイアログを表示する
6. ユーザーが確認して「はい」をクリックする
7. システムが写真を順次ゴミ箱に移動し、進捗を表示する
8. 完了後、システムが完了メッセージを表示する（完全削除はGoogle Photos画面から実行）

**代替フロー**:
- 4a: ユーザーがキャンセルした場合、処理を中止する
- 6a: ユーザーが「いいえ」を選択した場合、処理を中止する
- 7a: エラー発生時、状態を保存してエラーメッセージを表示する

### UC-02: 中断した処理を再開する

**アクター**: ユーザー

**事前条件**:
- 以前の削除処理が中断している
- 状態ファイルが存在する

**基本フロー**:
1. ユーザーがアプリケーションを起動する
2. システムが中断した処理があることを検知し通知する
3. ユーザーが「再開」ボタンをクリックする
4. システムが保存された状態から処理を再開する
5. 削除完了後、状態ファイルを削除する

## 6. 技術的詳細

### 6.1 リトライ戦略
- 最大リトライ回数: 3回
- バックオフ方式: 指数バックオフ
- 初回待機時間: 1秒
- 最大待機時間: 10秒
- 計算式: `min(10, 1 * 2^(retry_count - 1))` 秒

### 6.2 状態保存形式
```json
{
  "session_id": "uuid",
  "start_date": "2020-01-01",
  "end_date": "2020-12-31",
  "total_count": 15234,
  "processed_count": 5432,
  "last_processed_id": "photo_id_xxx",
  "status": "interrupted",
  "created_at": "2024-01-01T00:00:00Z",
  "updated_at": "2024-01-01T01:23:45Z"
}
```

## 7. 用語集

| 用語 | 定義 |
|------|------|
| ドライラン | 実際の削除を行わず、削除対象の確認のみを行う実行モード |
| ゴミ箱に移動 | Google Photosの「ゴミ箱に移動」操作。本ツールが行う最終操作。Google Photos側で60日後に自動削除される |
| レジューム | 中断した処理を途中から再開する機能 |
| 指数バックオフ | リトライ間隔を指数的に増加させる待機戦略 |
